## 6. 머신러닝 학습 활용 가능 여부 (판단)

- **양:** 한국어이면서 텍스트 중복이 아닌 리뷰 4,480건. 임시 라벨은 positive 5,366 / negative 708 / unlabeled 275로 **긍정이 매우 많다**(별점 4~5가 84.5%). 부정 학습 데이터를 늘릴 별점별 추가 수집은 수집 경로 문제로 하지 않았다.
- **시간순 검증:** 공식 업데이트 기간(2026-03-12 이후) 리뷰는 72건(GP 68, iOS 4)뿐이다. 최신 업데이트를 테스트 세트로 쓰기에는 매우 적다. 데이터 대부분이 2021~2023년(초기 버전)에 몰려 있다.
- **업데이트별 분석:** 리뷰가 많은 기간(v1.10~v1.60)에는 공식 패치노트가 없다. 그래서 "업데이트 내용 ↔ 반응 변화" 분석은 현재 데이터로는 불가능하다. 버전별 반응 분포까지만 볼 수 있다.
- **결론:**
  - 감성 분류 학습 데이터로는 **조건부로 사용 가능**하다(긍정 편향 보정, 검수 라벨 필요).
  - 업데이트별 분석 목적에는 **부족**하다. Google Play 적용일과 과거 패치노트가 없기 때문이다.
  - 출처 문제(7장)가 정리되기 전에는 최종 활용을 확정할 수 없다.

1. ~~**원본 리뷰의 출처 적법성**~~ → **최종 결정(2026-11-26): 스토어 웹에서 공개로 볼 수 있는 것만 사용한다(9장).** 기업 요청은 취소했다. 기존 `data/reviews.csv` 전체(6,349건)는 최종 데이터로 쓰지 않는다. 웹 화면과 지문이 일치한 436건만 `data/web/`에 둔다.

4. **업데이트 날짜 보완:**
   - Google Play 적용일과 v1.139 이전 패치노트는 공식 카페에 있지만, 카페는 robots.txt가 전체 금지다.

## 9. 최종 방향: 스토어 웹에서 공개로 볼 수 있는 데이터만 사용 (2026-11-26 결정)

8장의 기업 요청 방향은 **취소**했다(요청서는 보내지 않음). 대신 스토어 웹페이지에 공개적으로 표시되는 것만 쓴다. 결과는 `data/web/` 폴더에 있다.

### 9.1 방법

1. 브라우저로 스토어 웹페이지를 열람했다. 자동 수집 도구·비공식 API는 쓰지 않았다.
   - Google Play는 '리뷰 모두 보기' 창을 사람이 읽듯이 스크롤했다(1.5초 간격).
2. 화면에 보인 리뷰마다 지문을 기록했다(`data/sources/web_view_20261126/*.keys.json`).
   - 지문 = ID·별점·화면 날짜·공백 제거 본문의 SHA-1 앞 12자
3. `scripts/build_web_view_dataset.py`가 팀 파일(`reviews.csv`)에서 지문이 **정확히 같은 행만** 가져온다.
   - 따라서 채택된 값(ID, 별점, 날짜, 본문, iOS 제목)은 모두 웹 화면에 보인 값과 같다.
   - 웹 화면에 없는 값(앱 버전, 시각, 개발자 답변)은 쓰지 않는다.
   - 공감 수는 웹 화면 값이다.
   - App Store 1건은 팀 파일에 없어서 화면 내용을 직접 옮겼고, 지문으로 정확성을 확인했다.
4. 이후 정제·버전 매핑·검증은 같은 스크립트로 `data/web/`에 실행한다.
   ```
   python scripts/build_web_view_dataset.py
   python scripts/preprocess_reviews.py --in data/web/reviews_web.csv --out-dir data/web
   python scripts/collect_updates.py --reviews data/web/cleaned_reviews.csv --out data/web/updates.csv
   python scripts/match_versions.py --reviews data/web/cleaned_reviews.csv --updates data/web/updates.csv --out-dir data/web
   python scripts/validate_dataset.py --data-dir data/web
   ```

### 9.3 버전 매핑 결과와 한계

- **매핑 0건, 미분류 436건.**
  - Google Play 웹에는 앱 버전이 표시되지 않고, 공식 배포일도 공개되어 있지 않다(426건).
  - App Store 웹 리뷰 10건은 모두 공식 버전 기록이 시작되기 전(2022~2025)에 작성되었다.
- 업데이트 데이터는 App Store 공식 버전 기록 25개(4장)뿐이다.
- 따라서 **공개 웹 데이터만으로는 "업데이트별 리뷰 반응" 분석을 할 수 없다.** 할 수 있는 것은 작성일 기준 시계열 분석과 별점·감성 분포 분석이다.

### 9.4 날짜 기준에 관한 발견

- Google Play 웹 화면의 날짜는 팀 파일 시각에서 9시간을 뺀 날짜와 200건 모두 일치했다. 팀 파일 시각이 한국 시간(수집 PC 현지 시각)이라면, **Google Play 웹 날짜는 UTC 날짜**로 보인다.
  - 그래서 웹 데이터의 `published_at`은 날짜만 두고 `published_at_basis=utc_date`로 표시했다. 시각이 없어 KST로 바꿀 수 없다.
  - 이 결과는 GameVoiceLab B-03의 가정("Google Play 화면 날짜 = KST")과 다르다. 그쪽 데이터도 하루씩 어긋날 수 있으므로 확인이 필요하다.

## 8. 기업 공식 데이터 요청 및 처리 절차 — 취소됨 (9장으로 대체)

- 요청서 초안: [docs/official-data-request.md](../docs/official-data-request.md) — 팀 검토 후 발송(**미발송**)
- 요청 항목:
  - Play Console 리뷰 내보내기
  - 플랫폼별 버전 출시 이력(실제 배포일)
  - 패치노트
  - App Store Connect 리뷰
  - 원스토어 리뷰
- 데이터를 받으면(웹 수집 없음, `review-analysis/` 폴더에서):
  ```
  python scripts/import_official_exports.py --gp "<받은폴더>/reviews_*.csv" --asc "<받은폴더>/asc_reviews.json" --out data/official/reviews_official.csv
  python scripts/preprocess_reviews.py --in data/official/reviews_official.csv --out-dir data/official
  python scripts/collect_updates.py --official-csv "<출시이력>.csv" --reviews data/official/cleaned_reviews.csv --out data/official/updates.csv
  python scripts/match_versions.py --reviews data/official/cleaned_reviews.csv --updates data/official/updates.csv --out-dir data/official
  python scripts/validate_dataset.py --data-dir data/official
  ```
  - 출시 이력 CSV 양식: `data/sources/official_release_history_TEMPLATE.csv` (열: platform, version, release_date(KST), notes, source)
  - App Store 공식 스냅샷은 `--snapshot`으로 함께 넣을 수 있다(기본값으로 포함됨)
- 가져오기 처리:
  - 작성자 닉네임과 기기명은 가져오지 않는다.
  - 여러 달 파일에 같은 리뷰가 있으면 마지막 수정본만 남긴다.
  - 원본 UTC 시각은 KST로 변환한다.
  - Play Console 내보내기에는 공감 수가 없어 null이다. App Store Connect 리뷰에는 앱 버전이 없어서, 같은 플랫폼의 공식 배포일로 추정한다(`date_estimated`).
- 같은 플랫폼·버전의 적용일이 공식 출처끼리 다르면 `collect_updates.py`가 오류로 중단한다(임의 선택 금지).
- 시험 결과(2026-11-26): 테스트 전용 가상 파일로 전체 흐름을 실행했고, 위 처리와 검증이 모두 기대대로 동작했다. 가상 파일은 작업용 임시 폴더에만 두었고, 이 저장소의 데이터에는 섞지 않았다.
  - 검증 PASS, 중복 1건 병합
  - UTC→KST 날짜 변경 처리
  - 닉네임·기기명 미포함
  - 날짜 추정 2건 모두 같은 플랫폼 공식 배포일 사용
  - 핫픽스를 직전 주요 업데이트 그룹에 연결
- 실제 공식 데이터로는 아직 실행하지 않았다(데이터 미수령).

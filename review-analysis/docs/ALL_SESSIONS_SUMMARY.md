## 4. 세션별 요약

### A. 리뷰 분석 (폴더 `261126AIDHackathon_`)

#### A1. "메인" — 리뷰 분석 본작업
- **요청**: 붙여 넣은 작업 지시문 하나입니다. 핵심은 다음과 같습니다.
  - kr/ko 리뷰 수집(GP 최대 2만, iOS RSS 최대), 앱 ID는 확인받고 진행
  - 감성은 내용 기준, 주제는 복수 선택 + 주제별 감성, 커뮤니티 표현 반영
  - 규칙 → 애매한 건 직접 판정 → 50건 검수
  - 교차표, 우선순위 점수, 장점, 추이 분석, 오프라인 `dashboard.html`
- **한 일**
  - `collect_reviews.py`를 새로 작성했습니다. App Store 0건 버그(`sortBy` 대소문자)를 고쳤고, 원본 보호용 `--force`를 넣었습니다.
  - 규칙 분류에서 중립이 1,493건으로 너무 많아 어휘를 보강했습니다.
  - 확신하는 4,319건은 규칙 판정, 나머지 2,030건은 판정 기준서(`RUBRIC.md`)로 서브에이전트 7개가 병렬 판정했습니다. 별점은 보여주지 않았습니다.
  - 검수 50건 결과: 감성 48, 주제 49, 주제별 감성 47 일치. AI 판정분은 16/16, 오판 3건은 모두 규칙 쪽 오타·은어였습니다.
  - 우선순위 점수 = 100×(0.5·부정 건수 + 0.3·좋아요 가중 + 0.2·최근 추세)
  - 최근 30일 리뷰가 6건뿐이라 추세 창을 6개월(57건)로 넓혔습니다(사용자 결정). 3% 미만 주제는 '기타'로 묶었습니다(광고 1.35%).
  - 주제는 지시된 3개(과금·버그·콘텐츠)에 5개(운영·밸런스/성장·UI/편의성·캐릭터/아트·광고)를 더했습니다. 승인 과정은 기록에서 확인 안 됨.
- **결과**: 버그 95% 부정, 운영 72% 부정(그중 43% 계정 문제), 캐릭터/아트 96% 긍정(68%가 '귀엽다'). v1.99 → v1.120에서 부정·혼합 17% → 39%.

#### A2. "GitHub 레포지토리 생성 및 정리"
- 루트 파일을 `scripts/`, `data/`, `dashboard/`, `work/`로 정리하고 경로를 고쳤습니다.
- 파이프라인 전체를 다시 돌려 결과 파일이 바이트 단위로 재현되는지 확인했습니다. `analysis.json`만 같은 건수 키워드의 순서 차이(3바이트)가 있었습니다.
  - 이 과정에서 `rule_confident` 계산이 `ml_classify.py`에만 있어 재실행이 깨지는 문제를 찾아 `classify.py`로 옮겼습니다.
- README, WORK_SUMMARY, requirements, .gitignore를 작성했습니다.
- **팀 저장소가 비어 있지 않아서**(오토 밸런싱 도구, 미션 폴더, `v1-submit` 태그) 강제 푸시하지 않았습니다. 원격 최신 커밋 위에 `review-analysis/` 하위 폴더로만 추가했습니다(`481e0e4`).
- 남긴 주의: 로컬 저장소는 팀 저장소의 복사본이 아닙니다(공통 조상 없음). 이후 변경은 `review-analysis/`에 다시 얹어야 합니다.

#### A3. "메인 세션 작업 내용" — ML 분류기, 웹 점검, 접근성, API 서버
- **LLM 없는 분류**: TF-IDF + 로지스틱 회귀를 추천하고 구현했습니다. 규칙이 확신하는 리뷰는 규칙, 애매한 리뷰는 ML 3개(감성·주제·주제별 감성)가 판정합니다.
- **성능 변화** (어려운 2,030건 감성): 규칙 62.2% → 1차 80.1% → 개선 81.9% → 문장 임베딩 84.0%
  - 개선 내용: Kiwi 형태소, 애매한 리뷰 가중치 5배, 주제 기준 0.4
  - 임베딩 비교: ko-sroberta 84.0% > e5-small 82.5%
- **웹 적용 점검과 수정**
  - 모델 클래스가 `__main__`으로 저장되는 문제, 캐시 무한 증가·동시 쓰기, 상대 경로, 불러오기만 해도 바뀌는 출력 설정을 고쳤습니다.
  - 서빙 API `classify_reviews()`를 추가했습니다.
- **대시보드 접근성 13건 수정**: 차트 15개에 '표로 보기', 색 대비 기준 충족, ARIA·제목 구조·표 caption, 375~1280px에서 가로 스크롤 없음.
- **로컬 API 서버** (`server/app.py`, 표준 라이브러리만 사용)
  - 잘못된 요청 15종을 막는 것을 확인했습니다.
  - 요청 스레드마다 PyTorch가 메모리를 잡아 2.6 → 5.1GB로 늘던 문제를 **판정 전용 스레드 1개**로 해결했습니다.
- **2차 개선 모델로 재검증**
  - 메모리 약 2.6GB (4,000건 부하 중 2.54 → 2.62GB 유지)
  - 속도: 규칙 판정 1건 7ms, ML 판정 1건 약 190ms(이전 60ms), 50건 묶음 약 2초, 초당 약 11~12건
  - 미세조정 모델 폴더가 없으면 경고 후 기존 모델로 판정하도록 했습니다(`0883f26`). 폴더가 없으면 ML 판정 1,998건 중 29건의 감성이 달라집니다.

#### A4. "모델 학습 정확도 및 언어 이해 개선" — 심사용 보고서
- 사용자가 공식 심사표를 붙여 넣었고, 그 기준에 맞춰 `IMPROVEMENT_REPORT.md`를 새로 썼습니다.
- 사용자가 "강화학습"이라고 부른 것을 **"문장 임베딩 특징을 추가한 재학습"**으로 바로잡아 적었습니다. 심사에서 지적받을 수 있어서입니다.
- 새로 맞힌 76건, 새로 틀린 32건처럼 리뷰 단위 비교를 넣었고, 새로 틀린 리뷰도 숨기지 않았습니다.
- 찾은 공백: 웹앱 테스트 4종 없음, 최상위 `index.html` 없음, 팀원 역할 비어 있음.

#### A5. "플레이스토어 데이터 추출 확대" — 조사만 함
- 스토어의 "리뷰 6.79만"은 글 없는 별점까지 센 평점 수(73,387)였습니다. 글 있는 한국어 리뷰는 표시 6,176건이고 받은 것은 6,199건이라 **이미 전량**입니다.
- 별점별로 다시 받아 합계(556+129+268+613+4,633 = 6,199)가 같은 것으로 누락이 없음을 확인했습니다.
- 더 받을 수 있는 것은 외국어 리뷰뿐입니다(GP 약 10,175건, App Store 다른 국가 약 694건). 규칙과 임베딩이 한국어 전용이라 합치지 말라고 권했고, 수집하지 않았습니다.

#### A6. "달토끼 키우기 데이터 편향 비교" — 고유 단어 점검
- 게임명·캐릭터·세계관·재화·콜라보 단어를 지우고 같은 조건으로 다시 학습·채점했습니다(`scripts/ablation_game_terms.py`).

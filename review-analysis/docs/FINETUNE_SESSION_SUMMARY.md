실험별 수치를 더 자세히 보려면 [MODEL_TUNING.md](MODEL_TUNING.md)를 보세요. 심사용 서술은 [IMPROVEMENT_REPORT.md](IMPROVEMENT_REPORT.md)에 있습니다.

## 2. 요청과 출발점

**요청**
1. 임베딩 모델 미세조정
2. 가벼운 개선 4가지
   - 클래스별 판정 기준 조정
   - 여러 모델의 확률 평균
   - 잡음 라벨 가중치 낮추기
   - 오타·은어 사전 보강

**먼저 확인한 것**
- **메인 세션 작업 내용**: 개선 제안 목록이 출발점이었습니다. 메인 세션은 같은 시간에 서버 메모리 문제를 고치고 있었습니다.
- **데이터 수집**: "플레이스토어 데이터 추출 확대" 세션 결과를 확인했습니다. 글이 있는 한국어 리뷰는 이미 6,199건을 모두 받았습니다. 별점 1~5점으로 나눠 다시 받아 봐도 합계가 같았습니다. 스토어의 "리뷰 6.79만"은 글 없는 별점까지 센 숫자입니다. 그래서 **추가로 수집할 데이터는 없었습니다.**
- **기준 모델**: TF-IDF + 고정 임베딩(`jhgan/ko-sroberta-multitask`) + 로지스틱 회귀였습니다. 어려운 리뷰 84.0%였습니다.
- **환경**: CPU 전용(4코어 8스레드)입니다. GPU(MX450)는 드라이버가 CUDA 11.0이라 쓸 수 없었습니다.

## 4. 각 개선의 결과

어려운 리뷰 2,030건 감성 정확도 기준입니다.

| 방법 | 미세조정 없이 | 미세조정과 함께 | 채택 |
|---|---:|---:|:-:|
| 기준 (이전 모델) | 84.0% | — | |
| 오타·은어 사전 보강 | 85.1% | (기본 포함) | ✅ |
| 판정 기준 조정 | -0.1~+0.7%p | **-0.9%p** | ✗ |
| 확률 평균 (TF-IDF·임베딩 따로) | 84.9% (+판정 기준 85.6%) | 89.8% (+0.1%p, 2건) | ✗ (단순한 쪽 선택) |
| 잡음 라벨 가중치 낮추기 | 85.0% | 89.7% (0) | ✗ |
| **임베딩 모델 미세조정** | — | 단독 89.0%, **기존과 평균 89.7%** | ✅ |
| 주제 확률도 평균 | — | 주제 완전일치 +1.1%p, 버그 부정 640 → 704건 | ✗ |

### 4-1. 임베딩 모델 미세조정 — `scripts/finetune.py` (새 파일)
- `jhgan/ko-sroberta-multitask`를 감성(4클래스)과 주제(8개 이진)를 함께 배우도록 학습시켰습니다.
- 입력은 `"별점 N점. 리뷰 내용"` 형식입니다. AI가 판정한 리뷰는 손실 가중치 3배입니다.
- 하위 6개 층을 고정하고 3 epoch 학습했습니다. 학습률은 인코더 4e-5, 분류 헤드 1e-3이고 최대 128토큰입니다.
- 겹별 감성 정확도(어려운 리뷰, 미세조정 단독): 87.7% · 89.2% · 88.7% · 89.9% · 88.4% → 평균 88.8%입니다.
- 사용법: `cv`(교차검증, 약 70분), `train`(최종 학습, 약 20분)

### 4-2. 오타·은어 사전 보강 — `scripts/classify.py`
- `POS_SLANG`(긍정 예: 좋와, 괜판, 쟈미, 제밌, 커여, ㄱㅊ, 순삭)과 `NEG_SLANG`(부정 예: 현질게임, 짭, 극혐, 확률그지, 별루, 드럽)을 추가했습니다. 모두 약 100개입니다.
- 오탐 때문에 빼거나 좁힌 패턴이 있습니다.
  - "할게 없어서 해봤는데 재밌다"의 `할게없` → `할(게|거|꺼)읎`만 남김
  - "할망함"의 `망함` → `(?<!할)망함`
  - "어려분"(=여러분)의 `어려` → `어려(?!분)`
- 효과
  - 규칙이 만든 정답 96건이 바뀌었습니다(중립→긍정 69, 중립→부정 25, 기타 2).
  - 어려운 리뷰 2,030건의 정답(AI 판정)은 0건 바뀌었습니다.
  - 규칙 단독 정확도는 62.2% → 64.3%입니다.
  - 검수에서 지적된 "주아", "현질게임"이 바로잡혀 검수 감성이 48/50 → 50/50이 됐습니다.

### 4-3. 채택하지 않은 것과 이유
- **판정 기준 조정**: 다른 겹에서 정한 보정값을 적용하는 방식으로 평가했습니다. 미세조정 모델의 확률이 이미 잘 맞아서, 합친 뒤에는 정확도가 떨어졌습니다.
- **잡음 라벨 가중치**: 학습 겹 안에서 다시 교차검증해, 규칙 라벨 중 정답 확률이 15% 미만인 리뷰의 가중치를 0.2로 낮췄습니다. 해당 리뷰는 겹당 10~18건뿐이었고 효과는 0이었습니다. 사전 보강이 그런 라벨을 이미 바로잡았기 때문입니다.
- **주제 확률 평균**: 버그 부정 언급이 정답보다 10% 부풀었습니다. 대시보드 우선순위가 왜곡되어 `FT_TOPIC_W = 0`으로 껐습니다.

## 7. 진행 중 겪은 문제와 처리

| 문제 | 처리 |
|---|---|
| 정답이 바뀌면 층화 분할도 바뀌어 미세조정 결과와 겹이 어긋남 | 사전 보강 전 정답으로 만든 분할을 `work/cv_folds.csv`에 고정하고, 모든 실험이 이 분할을 쓰게 함 |
| 미세조정 로그의 손실이 0.007처럼 비정상적으로 낮게 찍힘 | epoch 경계에서 누적값이 초기화되는 로그 계산 버그였음 (학습 자체는 정상). 수정함 |
| 메인 세션이 `hybrid_predict`를 "애매한 리뷰만 ML로" 바꿔 행 위치가 어긋남 | 미세조정 확률을 행 번호가 아니라 리뷰 입력 문자열로 찾도록 구현 |
| 메인 세션과 `ml_classify.py`를 동시에 수정 | 반영 직전에 다시 읽고, 바꿀 부분만 고침 |
| 사전 보강으로 원래 규칙 확신 리뷰 1건이 애매해짐 (AI 판정 없음) | `merge_labels.py`에서 10건 이하면 규칙 판정으로 대체 |
| 문서에 "주제별 부정 건수 ±5% 안"이라고 잘못 씀 (과금은 155 → 178) | "버그는 정답과 거의 같고 나머지는 이전 모델과 비슷"으로 정정 |

## 8. 배포·사용 관련 정리

- **대시보드(`dashboard.html`)**: 수치가 파일에 들어 있어 모델과 무관하고, 어디서든 열립니다.
- **웹으로 들어오는 사용자**: 받을 것이 없습니다. 모델은 서버에서만 돕니다.
  - 서버 실측(세션 "메인 세션 작업 내용"): 규칙으로 판정되는 1건 7ms, ML로 판정되는 1건 약 60ms → 약 190ms, 50건 묶음 약 2초입니다.
  - 이 세션에서 잰 54ms는 서버를 거치지 않은 프로그램 내부 호출 값이라 서버 응답 시간과 다릅니다.
- **서버를 띄우는 사람**
  - 서버 컴퓨터에 `work/ft/model/`이 있어야 합니다. 폴더를 복사하거나 `python scripts/finetune.py train`(CPU 약 20분)으로 만듭니다.
  - GitHub는 파일 하나에 100MB까지라 저장소에 바로 넣을 수 없습니다.
  - 폴더가 없으면 경고를 출력하고 기존 모델로만 판정합니다(커밋 `0883f26`, 세션 "메인 세션 작업 내용"). 이 경우 ML 판정 1,998건 중 29건의 감성이 달라집니다.
  - 서버 메모리는 약 440MB 늘어납니다.

## 10. 재현 방법

```powershell
python scripts/classify.py              # 규칙 판정 (사전 보강 반영) → work/rule_labels.csv
python scripts/merge_labels.py          # 정답 라벨 재생성 → data/reviews_labeled.csv
python scripts/finetune.py cv           # 미세조정 5-겹 교차검증 → work/ft/oof_*.npy (약 70분)
python scripts/experiments.py oof       # 가벼운 개선 비교용 확률 → work/exp/
python scripts/experiments.py report    # 조합 비교표
python scripts/ml_classify.py eval      # 공식 평가 → work/ml_eval.json
python scripts/finetune.py train        # 미세조정 최종 모델 → work/ft/model/ (약 20분)
python scripts/ml_classify.py train     # 로지스틱 회귀 최종 모델 → work/ml_model.joblib
python scripts/ml_classify.py predict   # 전체 재분류 → data/reviews_labeled_ml.csv
python scripts/analyze.py               # 대시보드 수치 → work/analysis.json
python scripts/build_dashboard.py       # 대시보드 → dashboard/dashboard.html
```

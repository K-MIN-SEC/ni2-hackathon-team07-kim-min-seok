## 1. 직접 실행한 테스트

규칙이 확신하는 나머지 4,319건은 정답이 곧 규칙 판정이라 정확도가 높게 나올 수밖에 없어서, **어려운 2,030건을 핵심 지표**로 삼았습니다.

## 2. 발견한 오류와 수정 전후

### 오류 ① 규칙만으로는 어려운 리뷰의 38%를 틀림 → ML 분류기 도입 (1차)

- 키워드 규칙은 "재밌는데 렉이 심해요" 같은 장단점 섞인 리뷰, 감성어가 없는 리뷰에 약했습니다.
- 규칙 판정 결과와 별점, 글자·단어 패턴을 함께 쓰는 ML 분류기(TF-IDF + 로지스틱 회귀)를 만들었습니다.
- 어려운 리뷰 감성 정확도: **62.2% → 81.9%**

### 오류 ② 1차 모델이 단어만 보고 판정 → 문장 임베딩 추가 (개선)

**원인**: 1차 모델의 특징은 모두 "어떤 단어가 들어 있는가"였습니다. 그래서 단어는 달라도 뜻이 같은 표현을 묶지 못했습니다.
그리고 "스트레스", "환불"처럼 부정적으로 보이는 단어가 있으면 긍정 문장도 부정으로 판정했습니다.

**수정**: 로컬 한국어 문장 임베딩 모델 `jhgan/ko-sroberta-multitask`로 리뷰의 뜻을 벡터로 바꿔 특징에 추가했습니다.
- 전체 감성 모델과 주제별 감성 모델 모두에 적용했습니다.
- 로컬에서 계산하므로 새 리뷰를 분류할 때 **LLM 토큰이 들지 않습니다.**

### 오류 ③ 범용 임베딩이 "걱정·요청"과 "불만"을 구분하지 못함, 규칙이 오타를 못 읽음 → 미세조정 + 사전 보강 (2차 개선)

**원인**
- 임베딩 모델을 그대로 쓰고 그 위에 로지스틱 회귀만 학습했습니다. 그래서 모델은 "뜻이 비슷한가"만 알고 "감성이 같은가"는 배우지 못했습니다.
- 규칙 사전에 오타·은어("좋와요", "괜판", "현질게임")가 없었습니다. 그래서 규칙이 만든 **정답** 중에도 틀린 것이 섞여 있었습니다. 검수에서 나온 오판 3건 중 2건이 이 유형입니다.

**수정**
1. **임베딩 모델 미세조정** (`scripts/finetune.py`): `jhgan/ko-sroberta-multitask`를 우리 라벨로 감성·주제를 함께 배우도록 직접 학습시켰습니다. 노트북 CPU에서도 돌도록 아래 6개 층은 고정했습니다(교차검증 한 겹 약 14분). 최종 감성은 기존 모델 확률 0.4 + 미세조정 모델 확률 0.6으로 정합니다.
2. **오타·은어 사전 보강** (`scripts/classify.py`): 교차검증 오판 목록을 보고 약 100개 표현을 추가했습니다. 이 과정에서 **규칙이 만든 정답 96건이 바로잡혔습니다**(대부분 중립 → 긍정). AI가 판정한 어려운 2,030건의 정답은 바뀌지 않아서 수정 전후 비교는 공정합니다.
3. 함께 시험했지만 채택하지 않은 것: 판정 기준(클래스별 문턱) 조정, 의심 라벨 가중치 낮추기, 주제 확률 평균. 앞의 두 개는 효과가 없었고, 주제 확률 평균은 버그 부정 건수를 640 → 704건으로 부풀려 우선순위를 왜곡했습니다. 자세한 수치는 [MODEL_TUNING.md](MODEL_TUNING.md)에 있습니다.

### 점검 — 이 게임에만 나오는 단어를 외워서 맞힌 것은 아닌가

**의심**: 학습 데이터가 모두 '달토끼 키우기' 리뷰라서, 모델이 게임명·캐릭터 이름 같은 **이 게임 고유 단어**로 감성을 판정하고 있을 수 있습니다.
그렇다면 다른 게임 리뷰에는 쓸 수 없는 모델이 됩니다.

**확인 1 — 모델이 실제로 고유 단어를 배웠는가**: 배웠습니다. 학습된 감성 모델의 어휘 특징 38,095개 중
'달토끼'가 120위(긍정 쪽), '이터널리턴'이 594위, '루비'가 850위입니다. 주제 모델에서도 '루비'는 과금·콘텐츠, '니아'·'달토끼'는 캐릭터/아트 판정에 쓰였습니다.
다만 고유 단어 특징이 전체 가중치에서 차지하는 비중은 **0.47%** 이고, 상위 1,000개 특징 중에는 7개뿐입니다.

**확인 2 — 지우면 결과가 바뀌는가**: 아래 단어를 리뷰에서 지우고 **같은 정답·같은 5-겹 분할·같은 설정**으로 다시 학습·채점했습니다.
리뷰 6,349건 중 260건(4.1%), 어려운 리뷰 2,030건 중 193건에 이 단어가 들어 있습니다.
규칙 판정은 두 경우 모두 원본 텍스트로 계산했습니다. 사람이 만든 규칙은 그대로 두고 ML이 배운 부분만 비교하기 위해서입니다.

| 분류 | 지운 단어 (리뷰 본문에 실제로 나온 표기) |
|---|---|
| 게임명 | 달토끼, 달토끼 키우기, 달키, 토끼 등 |
| 캐릭터 | 니아, 린, 유나, 미호, 레니, 에스더, 라이아나 |
| 세계관 | 수호자, 어둠의 시련, 초월체 |
| 재화·아이템 | 루비, 당근, 드래곤 바주카 |
| 콜라보 | 이터널리턴, 스텔라이브, 루미아섬 |

| 지표 (규칙+ML 하이브리드) | 원본 | 고유 단어 제거 | 차이 |
|---|---:|---:|---:|
| 감성 정확도 (어려운 2,030건) | 84.8% | 84.8% | +0.05%p |
| 감성 macro F1 (어려운 건) | 0.782 | 0.783 | +0.001 |
| 주제 완전일치 (어려운 건) | 63.4% | 63.7% | +0.3%p |
| 주제별 감성 완전일치 (어려운 건) | 55.0% | 55.3% | +0.3%p |
| 감성 정확도 (전체 6,349건) | 95.1% | 95.1% | +0.02%p |
| 검수 50건 감성 일치 | 48/50 | 48/50 | 0 |

- 고유 단어가 들어 있는 어려운 리뷰 193건은 **감성 판정이 한 건도 바뀌지 않았습니다** (83.9% → 83.9%).
- 판정이 바뀐 11건은 모두 고유 단어가 없는 리뷰로, 재학습할 때 생기는 흔들림입니다(5건 새로 맞힘, 4건 새로 틀림).
- 주제별 부정 언급 수도 거의 같아서(버그 626 → 627, 과금 178 → 175) **우선순위 결론은 바뀌지 않습니다.**

**결론**: 고유 단어를 지워도 '귀여워요', '렉', '과금' 같은 일반 표현과 문장 임베딩이 같은 정보를 전달합니다. 모델은 고유 단어에 기대어 판정하지 않습니다.
단, 이 점검은 **"이 게임 리뷰 안에서"** 고유 단어에 기대지 않는다는 것까지만 보여 줍니다. 방치형 RPG 장르 어휘('방치', '보스', '스킬')와 이 게임 리뷰의 말투는 그대로 남아 있으므로,
다른 게임에서도 잘 맞는지는 다른 게임 리뷰에 정답을 붙여 평가해야 알 수 있습니다 (4장 한계).

> 이 점검의 '원본' 수치(84.8%)는 현재 코드로 다시 돌린 값이라, 위 수정 전후 표의 84.0%와 조금 다릅니다. 두 실행은 같은 코드로 돌렸으므로 이 비교 자체는 공정합니다.

## 4. 데이터·AI 사용과 한계

| 항목 | 내용 |
|---|---|
| **데이터 출처** | Google Play 6,199건(공개 스크래퍼), App Store 150건(Apple 공개 RSS). 2021-06 ~ 2026-11 |
| **분류 방법** | ① 키워드 규칙 → ② 규칙이 확신하는 4,319건은 규칙 판정 사용 → ③ 나머지 2,030건은 ML 분류기 |
| **LLM 학습 라벨 사용** | **사용함.** 규칙이 확신하지 못한 2,030건을 AI가 판정해 학습 정답으로 썼습니다. 판정 기준은 `work/manual/RUBRIC.md`로 문서화했고, **별점은 보여주지 않고 내용만으로** 판정하게 했습니다 |
| **서비스 시 LLM 사용** | **사용하지 않음.** AI는 학습 데이터를 만들 때 한 번만 썼고, 새 리뷰 분류는 로컬 모델로만 돌아갑니다 |
| **검증** | AI 판정분 16건 검수 결과 16/16 일치. 전체 무작위 50건 중 48건 일치 → 규칙 사전 보강 후 50건 모두 일치 (감성 기준) |

**한계**
- 정답의 1/3이 AI 판정이고, 사람이 검수한 AI 판정분은 16건뿐입니다. 정확도 수치는 "AI 정답과 얼마나 같은가"이지 "사람 판단과 얼마나 같은가"가 아닙니다.
- App Store는 150건뿐이라 결과는 사실상 Google Play 리뷰를 반영합니다.
- 최근 6개월 리뷰가 57건이라 최근 추세 수치는 불안정합니다.
- 중립 판정이 가장 약합니다(F1 0.60, 1차 개선 때 0.50).
- 미세조정 교차검증은 사전 보강 **전** 정답으로 학습했습니다(규칙 정답 96건 차이). 채점에 쓴 어려운 2,030건의 정답은 같습니다. 최종 모델은 보강 후 정답으로 학습했습니다.
- 학습·평가 데이터가 모두 '달토끼 키우기' 리뷰입니다. 게임 고유 단어에는 기대지 않는다는 것을 확인했지만(2장 점검), 다른 게임 리뷰에서의 정확도는 아직 재지 않았습니다.

## 5. 개발 중 배운 점

- **정확도 숫자 하나로는 부족했습니다.** 전체 정확도는 94%대지만, 쉬운 리뷰가 대부분이라 생긴 착시였습니다. 어려운 리뷰만 따로 채점하고 오답을 유형별로 나눠 보니 진짜 약점(문맥)이 보였습니다.
- **희귀 클래스를 강조하는 설정이 오히려 결과를 망쳤습니다.** 클래스 가중치를 `balanced`로 주자 부정이 과다 판정되어, 콘텐츠 부정 건수가 정답 129건에서 332건으로 부풀었습니다. 운영자가 보는 우선순위가 왜곡되기 때문에 정확도와 함께 **주제별 부정 건수도 정답과 비교**하는 기준을 세웠습니다.
- **모델의 한계 중 일부는 라벨의 한계였습니다.** 같은 유형의 리뷰가 다르게 라벨링되어 있으면 모델도 일관되게 배울 수 없습니다. 모델을 바꾸기 전에 판정 기준부터 정리해야 한다는 것을 배웠습니다. 실제로 오타 사전을 보강하자 규칙이 만든 정답 96건이 바로잡혔고, "잡음 라벨 가중치 낮추기"는 더 할 일이 없어졌습니다.
- **좋은 개선이 다른 개선을 지웁니다.** 판정 기준 조정은 기존 모델에서 조합에 따라 -0.1~+0.7%p였지만, 미세조정 모델과 합친 뒤에는 오히려 -0.9%p였습니다. 개선 방법은 따로따로가 아니라 **최종 조합에서 다시 확인**해야 했습니다.

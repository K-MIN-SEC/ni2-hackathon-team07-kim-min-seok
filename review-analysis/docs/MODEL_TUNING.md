## 시험한 방법과 결과

어려운 2,030건 감성 정확도 기준이에요. 모두 규칙+ML 하이브리드로 쟀어요.

| 방법 | 정확도 | 채택 |
|---|---:|:-:|
| 이전 모델 | 84.0% | |
| ① 오타·은어 사전 보강 | 85.1% | ✅ |
| ② ① + TF-IDF·임베딩 모델 확률 평균 + 판정 기준 조정 | 85.6% | (③에 흡수) |

| ④ + 판정 기준 조정 | 88.8% | ✗ |
| ④ + 잡음 라벨 가중치 낮추기 | 89.7% | ✗ (효과 없음) |
| ④ + 주제 확률도 평균 | 주제 완전일치 +1.1%p | ✗ (아래 참고) |

### ① 오타·은어 사전 보강 — `scripts/classify.py`의 `POS_SLANG`, `NEG_SLANG`
- 교차검증 오판 목록과 "규칙은 중립인데 별점이 극단인 리뷰"를 보고 표현 약 100개를 추가했어요.
  - 긍정 예: 좋와, 괜판, 쟈미잇, 제밌, 커여워, ㄱㅊ
  - 부정 예: 현질게임, 사키짭, 극혐, 확률그지, 별루
- **규칙이 만든 정답 4,319건 중 96건이 바뀌었어요.** 대부분 "좋와요", "괜찬네요"처럼 정답이 원래 틀렸던 것들이에요(중립→긍정 69건, 중립→부정 25건). 검수에서 지적된 "주아", "현질게임"도 바로잡혔어요.
- `merge_labels.py`를 다시 돌려 `data/reviews_labeled.csv`를 갱신했어요. 출처 구성(규칙 4,319 / AI 2,030)은 그대로예요.
- 오탐을 막으려고 빼거나 좁힌 패턴도 있어요. "할게 없어서 해봤는데 재밌다"의 '할게없', "할망함"의 '망함', "어려분"(=여러분)의 '어려'예요.

### ③ 임베딩 모델 미세조정 — `scripts/finetune.py`
- `jhgan/ko-sroberta-multitask`를 우리 라벨로 직접 학습시켰어요. 감성(4클래스)과 주제(8개)를 함께 배우게 했어요.
  - 이전에는 임베딩을 고정하고 그 위에 로지스틱 회귀만 학습했어요.
- 입력은 `"별점 N점. 리뷰 내용"` 형식이에요. AI가 판정한 리뷰는 손실 가중치 3배를 줬어요.
- CPU에서 돌리려고 하위 6개 층을 고정하고 3 epoch 학습했어요. 길이가 비슷한 리뷰끼리 묶어 패딩도 줄였어요.
  - 교차검증은 한 겹에 약 14분, 전체 학습은 약 20분 걸려요.
- 단독으로도 이전 모델보다 3.9%p 높았어요. 이전 모델과 확률을 평균하면 0.7%p가 더 올라요.
- 고쳐진 대표 유형은 장단점이 섞인 리뷰예요(혼합 F1 0.78 → 0.87). 중립 오판정도 줄었어요(중립 정밀도 0.43 → 0.63).

### 효과가 없었던 것
- **판정 기준 조정**: 다른 겹에서 정한 보정값을 적용했어요. 미세조정 모델 없이는 조합에 따라 -0.1~+0.7%p였지만, 미세조정 모델과 평균한 뒤에는 오히려 0.9%p 낮아졌어요. 미세조정 모델의 확률이 이미 잘 맞춰져 있기 때문이에요.
- **잡음 라벨 가중치 낮추기**: 학습 겹 안에서 다시 교차검증해, 규칙 라벨인데 모델이 정답 확률을 15% 미만으로 본 리뷰의 가중치를 0.2로 낮췄어요. 해당 리뷰는 겹마다 10~18건뿐이었고 정확도 변화는 0이었어요. 사전 보강(①)이 이런 오답 라벨 대부분을 이미 바로잡았기 때문이에요.
- **주제 확률 평균**: 주제 완전일치는 63.7% → 64.8%로 올랐어요. 그런데 버그 부정 언급이 정답 640건 대비 704건으로 부풀었어요. 그러면 대시보드 우선순위가 왜곡돼서 쓰지 않았어요. 지금 설정에서는 버그 부정이 639건으로 정답(640건)과 거의 같고, 나머지 주제도 이전 모델과 비슷한 수준이에요(과금 178/155, UI 96/111 등).

## 재현 방법

```powershell
python scripts/classify.py              # 규칙 판정 (사전 보강 반영)
python scripts/merge_labels.py          # 정답 라벨 재생성
python scripts/finetune.py cv           # 미세조정 5-겹 교차검증 → work/ft/oof_*.npy (약 70분)
python scripts/experiments.py oof       # 가벼운 개선 비교용 확률 → work/exp/
python scripts/experiments.py report    # 조합 비교표
python scripts/ml_classify.py eval      # 공식 평가 → work/ml_eval.json
python scripts/finetune.py train        # 미세조정 최종 모델 → work/ft/model/ (약 20분, 저장소에는 안 올림)
python scripts/ml_classify.py train     # 로지스틱 회귀 최종 모델 → work/ml_model.joblib
```

설정값은 `scripts/ml_classify.py` 위쪽에 있어요(`FT_SENT_W`, `FT_TOPIC_W`, `SENT_SPLIT`, `SENT_BIAS`).

## 한계와 주의

- 미세조정 교차검증은 사전 보강 **전** 정답으로 학습했어요. 규칙 정답 96건이 달랐고, 어려운 2,030건 정답은 같아요. 최종 모델은 보강 후 정답으로 학습해서, 교차검증 수치는 약간 보수적일 수 있어요.
- 서빙 때 미세조정 모델(약 440MB)이 하나 더 메모리에 올라가요. 판정 속도도 느려져요. TF-IDF + 미세조정 모델만 쓰면 기존 임베딩 모델을 뺄 수 있지만, 그 경우 정확도는 89.4%로 0.3%p 낮아져요.
- 남은 오답 약 10%는 여전히 반어, "보통은 ~인데 이건 다르다" 대조, 요청형 리뷰예요. 요청형 리뷰는 정답 기준 자체가 흔들려요.

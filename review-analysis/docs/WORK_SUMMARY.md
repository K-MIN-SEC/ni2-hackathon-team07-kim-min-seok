# 작업 내용 정리 (2026-11-26 기준)

"달토끼 키우기" 스토어 리뷰 분석 작업을 처음부터 지금까지 단계별로 정리했습니다. 각 단계마다 무엇을 했는지, 왜 그렇게 했는지, 결과 수치가 어떻게 나왔는지 적었습니다.
실행 방법과 폴더 구조는 [README](../README.md)를 보세요.

---

## 0. 전체 흐름

```
스토어 리뷰 수집 ─▶ 규칙 분류 ─┬─ 확신 4,319건 ──────────────┐
 (collect_reviews)   (classify) │                            ├─▶ 최종 라벨 ─▶ 수치 계산 ─▶ 대시보드
                                └─ 애매 2,030건 ─▶ AI 수동 판정 ┘  (merge_labels)  (analyze)  (build_dashboard)
                                                                     │
                                                                     └─▶ ML 분류기 학습·평가 (ml_classify)
                                                                         = AI 없이 새 리뷰 분류
```

## 1. 리뷰 수집 — `scripts/collect_reviews.py`

- **Google Play**: `google-play-scraper`로 최신순으로 수집했습니다. kr/ko 기준 **6,199건**(2021-06-26 ~ 2026-11-17)으로, 앱 출시 무렵부터 전부입니다.
- **App Store**: Apple 공개 RSS 피드로 수집했고 **150건**(2022-06-25 ~ 2026-10-31)이 나왔습니다. RSS 한도는 이론상 약 500건이지만 실제로는 3페이지까지만 내려왔습니다.
- 출력은 `data/reviews.csv`(utf-8-sig)이고 컬럼은 `store, review_id, date, rating, version, title, content, thumbs_up, dev_reply, reply_date`입니다.
- 원본을 보호하려고, 출력 파일이 이미 있으면 `--force` 없이는 덮어쓰지 않게 했습니다.

## 2. 규칙 기반 1차 분류 — `scripts/classify.py` → `work/rule_labels.csv`

판정 원칙은 다음과 같습니다.
- **감성은 별점이 아니라 리뷰 내용으로** 판정합니다. 예를 들어 별점 5점에 불만만 적힌 리뷰는 부정입니다.
- **주제는 8개이고 복수 선택**할 수 있습니다: 과금 · 버그 · 콘텐츠 · 운영 · 밸런스/성장 · UI/편의성 · 캐릭터/아트 · 광고. 어느 주제에도 해당하지 않으면 `일반`으로 둡니다.
- 주제마다 **커뮤니티 표현까지 포함한 키워드 정규식**을 두었습니다. 예: 현질/무과금/천장, 팅김/버벅/무한로딩.
- **주제별 감성**은 주제 키워드가 들어 있는 절(clause)의 극성과, 키워드 자체의 극성으로 정합니다.
- **문의형** 리뷰는 구체적인 문제(버그, 계정 등)가 보이면 부정, 보이지 않으면 중립으로 판정합니다.

**애매 플래그**: 규칙이 확신하지 못하는 경우를 표시했고, 6,349건 중 828건에 붙었습니다.

| 사유 | 건수 |
|---|---|
| 감성신호없음 | 463 |
| 장문 (150자 이상) | 159 |
| 부정인데 별점 5 | 64 |
| 혼합인데 주제 없음 | 49 |
| 긍정인데 별점 낮음 | 40 |
| 문의형 | 34 |
| 주제감성불명 (주제별 합계) | 135 |

**`rule_confident` (규칙 판정을 그대로 믿을 리뷰)**: 짧고(24자 이하) 애매 플래그가 없으며 주제 하나에 혼합이 아닌 리뷰, 또는 25~39자 길이의 `일반` 리뷰입니다. 이 기준으로 **4,319건은 규칙 판정을 그대로 쓰고, 나머지 2,030건은 AI 수동 판정**으로 넘겼습니다.

## 3. AI 수동 판정 — `work/manual/`

- 판정 기준은 [`work/manual/RUBRIC.md`](../work/manual/RUBRIC.md)에 정리했습니다. 감성 정의, 문의형·개선요청·부정어·반어 처리 방법, 주제별 포함 범위가 들어 있습니다.
- 2,030건을 **7개 배치**(`batch_0..6.jsonl`, 배치당 265~325건)로 나누어 AI가 판정했고, 결과는 `out_0..6.jsonl`에 있습니다.
- **별점은 일부러 보여주지 않고** 리뷰 내용만으로 판정하게 했습니다.

## 4. 병합 — `scripts/merge_labels.py` → `data/reviews_labeled.csv`

- 규칙 확신 건과 AI 판정 건을 합쳐 **최종 라벨 6,349건**을 만들었습니다(`label_source` = rule 4,319 / manual 2,030).
- 키워드 태그는 AI 판정 리뷰에도 붙도록 보조 사전(`KEYWORD_EXTRA`)을 추가했습니다. 예: 광고보상 미지급, 허위 광고, 진행/기능 오류.
- **비중이 3% 미만인 주제는 `기타`로 묶었습니다**(`work/grouping.json`). 현재는 `광고`(1.35%) 하나만 해당합니다.
- 추가 컬럼: `sentiment, topics, topics_grouped, topic_sentiments, sent_<주제>…, keywords, label_source`

## 5. 검수 — `work/audit_sample.csv`, `work/audit.json`

`random_state=2026`로 무작위 50건을 뽑아 검수했습니다(규칙 판정 34건, 수동 판정 16건).

| 항목 | 일치 |
|---|---|
| 전체 감성 | 48/50 → **50/50** |
| 주제 집합 | 49/50 |
| 주제별 감성 (주제·감성 모두 일치) | 47/50 → **49/50** |

- **수동 판정분 16/16, 규칙 판정분 31/34가 완전히 일치**했습니다.
- 오판 3건은 모두 규칙 쪽 짧은 리뷰에서 나왔습니다. 원인은 오타("주아"=좋아, "벌런스"=밸런스)와 감성어 없는 비판("현질게임")입니다.
- 이후 규칙 사전에 오타·은어를 보강해서 "주아"와 "현질게임"이 바로잡혔습니다(→ 화살표 오른쪽 값, [MODEL_TUNING.md](MODEL_TUNING.md) 참고). 이때 규칙이 만든 정답 96건이 함께 바뀌었습니다. "벌런스"(주제 누락)는 남아 있습니다.
- 한계: 무작위 표본의 2/3가 짧은 호평이라서, 길고 복잡한 리뷰의 정확도는 수동 판정분 16건으로만 확인했습니다.

## 6. 분석 — `scripts/analyze.py` → `work/analysis.json`

대시보드에 들어가는 **모든 수치는 코드로 계산**합니다. 사람이 손으로 넣은 숫자는 없습니다.

### 우선순위 점수 (주제·키워드 단위, 부정·혼합 언급 기준)

```
N = 해당 항목의 부정(혼합) 리뷰 수
W = Σ log2(1 + 좋아요 수)                 ← 공감 가중치, 극단값 완화
G = clip(r, 0, 3) / 3                     ← 최근 추세
    r = 최근 6개월 언급률(평활) / 이전 기간 언급률
    최근 언급률(평활) = (n_recent + 20·p_base) / (R_recent + 20)   ← 최근 표본이 작아 기준선 쪽으로 수축
Score = 100 × (0.5·N/N_max + 0.3·W/W_max + 0.2·G)
```

## 8. AI 없이 분류하기 — `scripts/ml_classify.py`

목표는 **새 리뷰가 들어와도 LLM 토큰 없이 분류**하는 것입니다. AI는 학습 데이터(2,030건)를 만들 때 한 번만 썼습니다.

**구조 (하이브리드)**
- 규칙이 확신하는 리뷰(`rule_confident`)는 규칙 판정을 그대로 씁니다.
- 애매한 리뷰는 ML 모델 3개로 판정합니다.
  1. 전체 감성 (4클래스)
  2. 주제 (주제마다 이진 분류기, 확률 0.4 이상이면 채택)
  3. 주제별 감성 (전체 감성이 혼합일 때만 사용하고, 나머지는 전체 감성을 따릅니다. 정답 라벨에서 98%가 이렇게 일치했습니다)
- **특징**: 글자 n-gram + 단어 n-gram + 형태소 원형(Kiwi) + 별점 + 규칙 판정 결과(감성어 수, 규칙 주제 등) + 로컬 한국어 문장 임베딩(`jhgan/ko-sroberta-multitask`)
- **모델**: TF-IDF + 로지스틱 회귀. 애매한 리뷰에 학습 가중치 5배를 주었고, 클래스 가중치는 쓰지 않았습니다. `balanced`로 하면 부정이 과다 판정되었습니다.
- **미세조정 모델 (2차 개선)**: 같은 임베딩 모델을 우리 라벨로 직접 학습시켰습니다(`scripts/finetune.py`). 전체 감성은 로지스틱 회귀 확률 0.4 + 미세조정 모델 확률 0.6으로 정합니다. 주제는 로지스틱 회귀만 씁니다. 자세한 실험은 [MODEL_TUNING.md](MODEL_TUNING.md)에 있습니다.

**5-겹 교차검증 결과**

| 방법 | 감성 정확도 (애매 2,030) | 감성 정확도 (전체 6,349) | 주제 완전일치 (애매) | 주제별 감성 완전일치 (애매) |
|---|---|---|---|---|
| 규칙 단독 | 62.2% | 87.9% | 49.8% | 30.6% |
| 1차 규칙 + ML (TF-IDF만) | 81.9% | 94.2% | 61.9% | 51.5% |
| 규칙 + ML (+ 고정 임베딩) | 84.0% | 94.9% | 63.9% | 54.9% |
| **규칙 + ML (+ 사전 보강 + 미세조정, 현재)** | **89.7%** | **96.7%** | **63.7%** | **56.9%** |

규칙 단독은 사전 보강 뒤 64.3% / 88.6% / 49.8% / 32.1%입니다. 전체 6,349건 수치는 사전 보강으로 규칙 정답 96건이 바뀐 뒤의 값이라, 이전 행과 엄밀하게 같은 기준은 아닙니다. 어려운 2,030건의 정답은 같습니다.

- 애매 건 감성의 클래스별 F1 (현재): 긍정 0.93 · 부정 0.92 · 혼합 0.87 · **중립 0.60**. 중립이 여전히 가장 약합니다(1차 0.47).
- 주제별 부정 건수는 정답과 비슷하게 나왔습니다(정답 → 교차검증 예측. 예: 버그 640 → 639, 운영 223 → 226, 과금 155 → 178).
- 전체를 다시 분류한 결과는 `data/reviews_labeled_ml.csv`(rule 4,351 / ml 1,998)입니다. 오타·은어 사전 보강으로 규칙이 확신하는 리뷰가 32건 늘었습니다.

## 9. 한계와 주의할 점

- **App Store 표본이 작습니다**(150건). 결과는 사실상 Google Play 리뷰를 반영합니다.
- **최근 6개월 리뷰는 57건**(최근 30일 6건)뿐입니다. 그래서 추세 항목(G)은 평활로 보정했지만 여전히 불안정합니다.
- 정답 라벨의 1/3(2,030건)이 AI 판정입니다. 검수에서는 16/16이 일치했지만 표본이 작습니다.
- 미세조정 모델 때문에 서빙 메모리가 약 440MB 늘고 판정이 느려집니다.
- ML의 **중립 판정이 여전히 가장 약합니다**(F1 0.60). 오타는 사전 보강으로 일부 잡지만, 이모지만 있는 리뷰("💖")나 반어는 아직 놓칩니다.
- `analyze.py`를 다시 돌리면 건수가 같은 키워드끼리 나열 순서가 바뀔 수 있습니다. 수치 자체는 같습니다.

## 1. 한 줄 요약

모바일 방치형 RPG **"달토끼 키우기"**의 한국어 스토어 리뷰 **6,349건**을 감성·주제로 분류해 **고쳐야 할 우선순위**와 **지켜야 할 장점**을 찾고, 오프라인 대시보드와 **LLM 없이 동작하는 규칙 + ML 분류기**(어려운 리뷰 감성 정확도 62.2% → **89.7%**)를 만들었습니다.

## 2. 문제 정의

- 리뷰는 많지만 별점만으로는 **무엇이 왜 불만인지** 알기 어렵습니다. 별점 5점에 불만만 적힌 리뷰도 있습니다.
- 목표
  1. 리뷰마다 **감성**(긍정/부정/중립/혼합), **주제**(복수), **주제별 감성**, **키워드** 판정
  2. **"무엇을 먼저 고칠까"** 우선순위 점수 계산
  3. 결과를 오프라인 단일 HTML **대시보드**로 제공
  4. 새 리뷰를 **AI 토큰 없이** 분류하는 분류기 학습

### 분류 원칙

### 우선순위 점수

```
Score = 100 × (0.5·N/N_max + 0.3·W/W_max + 0.2·G)
  N = 부정·혼합 언급 수
  W = Σ log2(1 + 좋아요 수)        ← 공감 가중치
  G = clip(최근 6개월 언급률 / 이전 언급률, 0, 3) / 3   ← 최근 추세 (표본이 작아 평활)
```

**주제 단위**: 버그 **90.4** ≫ 운영 42.2 > 밸런스/성장 41.0 > 과금 36.6 > 콘텐츠 28.4 > UI/편의성 28.2

## 7. AI 없이 분류하기 — 규칙 + ML 분류기

### 구조 (하이브리드)
- 규칙이 확신하는 리뷰 → 규칙 판정 그대로
- 애매한 리뷰 → ML 3개: ① 전체 감성(4클래스) ② 주제(주제별 이진, 확률 0.4 이상) ③ 주제별 감성
- **특징**: 글자·단어 n-gram, Kiwi 형태소, 별점, 규칙 판정 결과, 한국어 문장 임베딩(`jhgan/ko-sroberta-multitask`)
- **모델**: TF-IDF + 로지스틱 회귀 (확률 0.4) + **미세조정 임베딩 모델** (확률 0.6) 평균

### 성능 추이 (5-겹 교차검증)

| 단계 | 어려운 2,030건 감성 | 전체 6,349건 감성 | 주제 완전일치 | 주제별 감성 |
|---|---:|---:|---:|---:|
| 규칙 단독 | 62.2% | 87.9% | 49.8% | 30.6% |
| ML 1차 (TF-IDF) | 80.1% | 93.7% | 59.3% | 48.6% |
| ML 개선 (Kiwi, 가중치) | 81.9% | 94.2% | 61.9% | 51.5% |
| + 고정 문장 임베딩 | 84.0% | 94.9% | 63.9% | 54.9% |
| **+ 오타·은어 사전 + 미세조정** | **89.7%** | **96.7%** | 63.7% | **56.9%** |

- 클래스별 F1(현재): 긍정 0.93 · 부정 0.92 · 혼합 0.87 · **중립 0.60**
- 주제별 부정 건수도 정답과 거의 같음 (버그 640 → 639, 운영 223 → 226)

### 개선 과정
1. **규칙만으로 38% 오답** → TF-IDF + 로지스틱 회귀 (62.2% → 81.9%)
2. **단어만 보고 판정** ("환불 잘해줌"을 부정으로) → 문장 임베딩 추가 (→ 84.0%, 76건 새로 맞힘 / 32건 새로 틀림)
3. **범용 임베딩이 걱정·요청과 불만을 구분 못 함, 규칙이 오타를 못 읽음**
   → 임베딩 모델 **미세조정**(CPU, 하위 6층 고정, 3 epoch) + **오타·은어 사전 약 100개** (좋와, 괜판, 쟈미잇, 현질게임, 극혐 …)
   → **89.7%** (167건 새로 맞힘 / 53건 새로 틀림, 순증 +114)

### 시험했지만 채택하지 않은 것
| 방법 | 결과 | 이유 |
|---|---|---|
| 클래스 가중치 `balanced` | 콘텐츠 부정 129 → 332건 | 우선순위 왜곡 |
| 판정 기준(문턱) 조정 | -0.9%p | 미세조정 모델 확률이 이미 잘 맞음 |
| 잡음 라벨 가중치 낮추기 | 변화 0 | 사전 보강이 이미 해결 |
| 주제 확률 평균 | 주제 일치 +1.1%p, 버그 부정 640 → 704 | 우선순위 왜곡 |

### 편향 점검 — 게임 고유 단어를 외운 건 아닌가?
- 게임명·캐릭터(니아, 린, 유나 …)·세계관·재화(루비, 당근)·콜라보(이터널리턴 …)를 지우고 같은 조건으로 재학습
- 어려운 리뷰 감성 **84.8% → 84.8%**, 고유 단어가 든 193건은 **판정이 한 건도 바뀌지 않음**
- 고유 단어 특징 비중은 전체 가중치의 0.47% → **판정이 고유 단어에 기대지 않음**

## 8. 로컬 API 서버

- `python server/app.py` → `http://127.0.0.1:8765`
- `GET /` 테스트 페이지, `GET /api/health`, `POST /api/classify` (최대 50건 · 256KB)
- 잘못된 요청 15종 차단 확인
- **메모리 누수 해결**: 요청 스레드마다 PyTorch 실행 시 2.6GB → 5.1GB → **판정 전용 스레드 1개**로 2.54 → 2.62GB 유지
- 속도: 규칙 판정 1건 약 7ms, ML 1건 약 190ms, 50건 묶음 약 2초, 초당 약 11~12건
- 미세조정 모델(약 420MB, git 제외)이 없으면 경고 후 로지스틱 회귀만으로 동작 (정확도 약 85%)

```python
ml_classify.load_model(serving=True)
ml_classify.classify_reviews([{"content": "재밌는데 렉이 심해요", "rating": 4}])
# → [{"sentiment": "혼합", "topics": {"버그": "부정"}, "source": "ml", "truncated": False}]
```

## 12. 배운 점 & 다음 단계

**배운 점**
- 전체 정확도 94%는 쉬운 리뷰가 만든 착시 → **어려운 리뷰만 따로 채점**하고 오답을 유형별로 나누니 진짜 약점(문맥)이 보임
- 정확도만이 아니라 **주제별 부정 건수**도 정답과 비교해야 우선순위가 왜곡되지 않음
- 모델의 한계 일부는 **라벨의 한계** → 판정 기준부터 정리
- 개선은 따로가 아니라 **최종 조합에서 다시 확인**해야 함

**다음 단계**
- "다만·근데·하지만"으로 **절을 나눠** 절 단위 감성 판정
- "(수정)" 뒤 내용을 최종 상태로 보고 가중치
- 요청·걱정·응원의 판정 기준 통일 후 재라벨링
- 확신도가 낮은 리뷰는 **"검토 필요"** 표시
- 다른 게임 리뷰로 일반화 성능 평가

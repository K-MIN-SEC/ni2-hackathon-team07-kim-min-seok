# 오토 밸런싱 (Auto Balancing)

게임 기획자가 **재화·성장 상태·능력치·모듈을 직접 구성**하고, 유저 유형별 성장 곡선·재화 흐름·이벤트 효과를 시뮬레이션하며, **목표에 맞는 수치를 자동으로 찾아 검증**하는 밸런싱 도구입니다.

2026 NI2.0 AID 해커톤 7팀 카페인 중독 (서일대학교 AI게임융합학과) · 연계 기업 ㈜에이블게임즈

> ⚠ 샘플·프리셋의 수치는 **가상 데이터**입니다. ㈜에이블게임즈의 실제 데이터나 공식이 아닙니다.
> 프로젝트는 사용하는 브라우저에만 저장됩니다 (서버·로그인·API 키 없음).

- 접속 주소 (GitHub Pages): https://k-min-sec.github.io/ni2-hackathon-team07-kim-min-seok/
- 이전 버전(v1, 고정된 방치형 RPG 계산기): `/v1/` · 제출 보존용 태그 `v1-submit`

## 사용 흐름

1. **프로젝트 홈** — 새 프로젝트 / 장르 프리셋(방치형 RPG) / JSON 불러오기 / 샘플 체험
2. **설정 마법사 (새 프로젝트)** — 7단계에서 실제로 게임 구조를 만든다
   1. 기본 정보 → 2. 재화·성장 상태·능력치 → 3. 수급 모듈 → 4. 소모·성장 모듈 → 5. 연결 규칙 → 6. 유저 모델 → 7. 검증·완료
3. **워크스페이스** — 마법사를 다시 거치지 않고 모든 항목을 자유롭게 수정
   - 게임 구조: 재화·상태·능력치 / 수급 시스템 / 소모·성장 / 연결 규칙 / 유저 모델 (편집하면 오른쪽 미리보기가 바로 갱신)
   - 밸런싱: 시뮬레이션 결과 / 이벤트 실험 / 목표 밸런싱 / 유저 비교
   - 파일: 프로젝트 JSON 가져오기·내보내기, 결과 CSV

## 핵심 기능

| 기능 | 내용 |
|---|---|
| 사용자 정의 구조 | 재화(골드·경험치·루비·입장권…), 성장 상태(레벨·강화 단계·스킬 레벨·스테이지…), 능력치(공격력·체력…)를 원하는 만큼. 모든 참조는 이름이 아닌 고유 ID |
| 모듈 조합 | 자동사냥·오프라인 방치·주기 보상·던전·레벨업·강화·진행 7종을 원하는 개수만큼. 각 모듈의 보상·비용 재화와 대상 상태를 직접 선택 |
| 연결 규칙 | 참조 → 적용 대상 → 효과 → 변화량 (예: 스킬 레벨 → 자동사냥 → 보상 +2%/레벨). 능력치 가산·배율, 보상·비용·처치 속도·소요 시간 |
| 보상 발생/수령 조건 | 출석형(접속 시) / 자동 지급(즉시·우편함) / 충전형 / 방치(한도까지 쌓이고 접속 시 수령) 구분 |
| 시뮬레이션 | 1분 단위, 성장 곡선·재화 흐름·해금 시점·수급처 비중·규칙 기반 분석(근거 수치 포함)·재화 잔액 검증 |
| 이벤트 실험 | 재화 지급·보상 배율·비용 할인·매일 추가 지급, 대상 조건. 원본을 바꾸지 않고 기준과 비교 |
| 목표 기반 자동 밸런싱 | 목표(상태 N 도달 / 콘텐츠 해금) + 목표 시간(이내 / 최대한 가깝게) + 변수별 범위·잠금 → 이분 탐색 또는 그리드 + 국소 정제 → **재시뮬레이션 검증** → 승인 후에만 원본 적용, 조정 입력값 CSV |
| 유저 비교 | 캐주얼·일반·헤비 등 유형별 곡선을 같은 밸런스·이벤트로 동시 비교, 격차 배율 |
| 신뢰성 | 무한대·1e300 초과·반복 한도 초과 시 '신뢰 불가' 경고, 목표 밸런싱 후보에서 제외 |

### 개발 중 발견한 문제와 개선

| 발견한 문제 | 개선 |
|---|---|
| 처음 샘플 값에서는 7일 이후 성장이 거의 멈추고 유저 유형 간 차이가 작았다 | 강화를 % 곱셈 방식으로 바꾸고 샘플 값을 다시 맞춤 |
| 던전이 1시간 안에 모두 열려 이벤트를 넣어도 해금 시점이 그대로였다 | 해금 조건 조정 → 경험치 2배 이벤트로 목표 도달이 약 2일 빨라지는 것 확인 |
| 접속 0분이어도 출석·방치 보상을 자동으로 받았다 (외부 검토) | 보상의 발생 조건과 수령 조건을 분리 |
| 시작 레벨이 최대 레벨을 넘어도 계산했다 (외부 검토) | 관계형 입력 검증 추가 |
| 수치 폭주 시 작은 경고만 떴다 (외부 검토) | ‘신뢰 불가’ 전체 경고 + 목표 밸런싱 후보 제외 |
| 고정된 게임 하나의 수치만 고치는 계산기였다 (외부 검토) | 데이터 구조 v2(모듈 조합형) + 프로젝트 홈·설정 마법사·워크스페이스 |
| 강화 모듈 여러 개를 '돌아가며' 강화하면 늘 첫 모듈만 샀다 | 다음 차례를 기억하도록 수정 (테스트 추가) |
| 목표 밸런싱 변수 경로 해석 버그 (ID 비교 중 인덱스가 여러 번 증가) | 수정 후 모든 변수 경로 읽기·쓰기 테스트 추가 |
| 연결 규칙 대상·이벤트 조건 변경 시 화면 오류 | ID로 끝나는 경로 해석 수정, 브라우저에서 재확인 |

## 모델의 한계와 가정

- 확률(가챠·확률 강화)은 아직 없습니다. 같은 입력이면 항상 같은 결과입니다.
- 처치 속도는 기본적으로 능력치와 무관합니다. 연결 규칙의 ‘처치 속도’를 추가하면 능력치 → 처치 속도를 직접 연결할 수 있고, 연결하지 않은 프로젝트에는 화면에 한계를 표시합니다.
- 유저는 하루 한 번, 정한 시각에 접속합니다 (하루 여러 번 접속은 후순위).
- 결과는 설정한 유저 모델에 따른 예측이며, 실제 이용자 데이터가 아닙니다.
- 후순위: 데이터 테이블 공식, CSV 컬럼 매핑 가져오기, 재화 교환 모듈, 확률·가챠.
